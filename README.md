# Input and oracle errors in unit tests written by language models

Code, model replies and analysis for the paper *Input and oracle errors in unit tests generated by language models*
(O. Kholodniak).

Three models write six literal assertions (`assert f(args) == expected`) for each of 157 HumanEval+ functions, given
the signature and docstring (`spec`), the reference implementation as well (`code`), or a mutated implementation
(`buggy`). Every assertion is classified against the reference solution as a non-executable input (the reference raises or
times out), a wrong expected value or correct, and each suite is scored on behaviour-changing mutants of its function:

| Measure | Meaning |
|---|---|
| filtered detection | share of mutants on which a correct assertion fails (wrong assertions removed) |
| corrected detection | share of mutants whose outcome differs from the reference on a valid input of the suite |
| oracle loss | corrected − filtered: detection lost only through wrong expected values |
| bug detected / encoded | for `buggy`: a correct assertion fails on the shown mutant / an assertion expects the mutant's output |

Mutants: first-order replacements of arithmetic, comparison and boolean operators, integer constants ±1 and removal of
`not` in the function body, kept only if some HumanEval+ input changes the outcome (value, exception or timeout);
identical outcome vectors merged, at most 15 per function (1,226 mutants, 145 functions).

## Data and models

- [HumanEval+](https://huggingface.co/datasets/evalplus/humanevalplus) (Apache-2.0) and the original
  [HumanEval](https://huggingface.co/datasets/openai/openai_humaneval) tests (MIT), downloaded on first use;
  `data/tasks.json` holds the 157 eligible tasks with their inputs and reference outputs (Python literals),
  `data/mutants.json` the kept mutants.
- Local models (Ollama 0.34.3, Apple M1 Pro, Q4_K_M): `qwen2.5-coder:7b` (digest dae161e27b0e), `gemma3:4b`
  (a2af6cc3eb7f). API model: `deepseek/deepseek-v3.2` on OpenRouter. Temperature 0, at most 800 output tokens.

## Layout

```
src/testoracle/   tasks, sandboxed execution, mutation, prompts and parsing, experiment, report
data/             tasks.json, mutants.json, excluded_tasks.json
results/          generations.jsonl (raw model replies with times and tokens), scores.jsonl, summary.json,
                  assertions.png
tests/            unit tests
PROTOCOL.md       plan written before generation; protocol_freeze.sha256 holds the hashes at that time
CHANGELOG.md      changes after the plan
```

Generated assertion statements are never executed as code: they are parsed with `ast`, only literal arguments are
accepted, and the predicate (`==`, `is`, truth value) is evaluated by the harness. The literal arguments are passed
to the reference solutions and their mutants, which run in child processes with a 2 s limit per call; a crashed or
stalled child is replaced and the run continues with the next input. Note that one task (HumanEval/160) evaluates
its string arguments with `eval`, as in the original benchmark. The original HumanEval tests are parsed in full and
compared with the generated suites on the functions where they yield parseable assertions.

## Usage

Python 3.11+ and [uv](https://docs.astral.sh/uv/). `requirements.lock.txt` lists the exact package versions used.

```bash
uv venv && uv pip install -r requirements.lock.txt && uv pip install -e ".[dev]" --no-deps
uv run --no-sync pytest
uv run --no-sync testoracle report   # results/summary.json and results/assertions.png from the stored scores
```

`score` and `generate` skip the runs already stored in `results/`. To rescore the stored replies, move
`results/scores.jsonl` aside and run `uv run --no-sync testoracle score`.

New measurements, in a separate clone without `results/generations.jsonl` and `results/scores.jsonl`:
`uv run --no-sync testoracle tasks`, `uv run --no-sync testoracle mutants`, then
`uv run --no-sync testoracle generate qwen-coder-7b gemma3-4b deepseek-v3.2` (Ollama with the two local models;
`OPENROUTER_API_KEY` for DeepSeek) and `uv run --no-sync testoracle score`.
